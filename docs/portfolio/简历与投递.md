## 60–90 秒项目演示顺序

1. 工作室选择“面试”、22°C → 生成三套演示搭配 → 说明三套均由已有衣物组成。
2. 将温度改为 15°C → 观察外套约束；演示规则不代表真实模型质量已通过。
3. 保存一套 → “我的” → “我的方案”查看与删除。
4. 衣橱上传非私人衣物图 → 解释“当前是演示识别”，手动修正标签后入库。
5. 打开 GitHub 验证说明，讲清真实识别/点评的小样本通过与搭配超时这一未解决问题。

## 面试时可讲的关键取舍

- 为什么不直接做购物推荐：先验证已有衣橱的利用与决策支持，再考虑商业化。
- 为什么保留确认页：模型标签可能错，用户必须能修正，不让错误直接写入衣橱。
- 为什么不把超时放宽为 30 秒就宣布成功：诊断输出仍存在字段错误和缺鞋问题，延长等待不等于达到质量标准。
- 为什么公开 Mock：保证招聘演示可复现，不暴露密钥，不开放未具备鉴权和预算控制的付费网关。
